PRODUTO
-------
RideFriend é uma aplicação móvel (iOS + Android) que conecta passageiros
com motoristas da sua rede de confiança pessoal — família, amigos, colegas
de trabalho e vizinhos. Quando um utilizador chega a uma paragem de autocarro,
a app alerta automaticamente os motoristas conhecidos que estão próximos ou
que passam naquela rota. Não é um serviço de transporte pago — é coordenação
de boleias entre pessoas que já se conhecem.

STACK TECNOLÓGICA DEFINITIVA
------------------------------
- Frontend Mobile : React Native 0.74+ com Expo SDK 51 (managed workflow)
- Linguagem        : TypeScript (strict mode)
- Navegação        : React Navigation 6 (Bottom Tabs + Stack)

- Mapas            : react-native-maps com tiles OpenStreetMap (gratuito)
- Notificações     : Expo Notifications + FCM (Android) + APNs (iOS)
- Backend API      : Node.js 20 + Express + TypeScript (no VPS Hostinger)
- ORM              : Prisma (type-safe queries)
- Hosting          : Hostinger VPS KVM2 (Ubuntu 22.04), Nginx, PM2
- CI/CD            : GitHub Actions → SSH deploy automático
- SMS OTP Angola   : AfricasTalking API (operadores Unitel + Africell)

SCHEMA DA BASE DE DADOS (Supabase/PostgreSQL)
----------------------------------------------
Tabelas:
  users            id, phone, name, photo_url, home_area, is_driver,
                   rating_avg, ride_count, expo_push_token, created_at

  contacts         id, user_id, contact_user_id,
                   group_type ENUM('family','friend','colleague','neighbour'),
                   trust_level INT DEFAULT 1, created_at
                   [UNIQUE (user_id, contact_user_id)]

  locations        id, user_id, lat DECIMAL(10,8), lng DECIMAL(11,8),
                   accuracy FLOAT, mode ENUM('passenger','driver'),
                   is_active BOOL, heading FLOAT, speed FLOAT, updated_at
                   [INDEX on (user_id, is_active, updated_at)]

  rides            id, driver_id, passenger_id,
                   status ENUM('requested','accepted','in_progress',
                               'completed','cancelled'),
                   origin_lat, origin_lng, dest_lat, dest_lng,
                   distance_km FLOAT, started_at, ended_at, created_at

  ratings          id, ride_id, rater_id, rated_id,
                   score SMALLINT CHECK(score BETWEEN 1 AND 5),
                   comment TEXT, created_at

  notifications    id, user_id, type VARCHAR(50), payload JSONB,
                   is_read BOOL DEFAULT false, created_at

  sos_events       id, user_id, lat, lng, ride_id (nullable),
                   emergency_contact_id, triggered_at, resolved_at

Cria o motor de localização do RideFriend — a funcionalidade mais crítica
da app. Gera estes ficheiros:

1. src/utils/geo.ts
   - haversineDistance(lat1, lng1, lat2, lng2): number
     (retorna distância em km, precisão 2 casas decimais)
   - estimateETA(distanceKm: number, avgSpeedKmh = 30): number
     (retorna minutos, arredondado para cima)
   - isPointNearRoute(point, routeStart, routeEnd, radiusMeters): boolean
     (verifica se um ponto está perto de uma linha recta entre dois pontos)
   - formatDistance(km: number): string
     ("50 m" se < 1km, "1.2 km" se >= 1km)
   - formatETA(minutes: number): string
     ("1 min", "5 min", "Agora!" se <= 1 min)
   - reverseGeocode(lat, lng): Promise<string>
     (chama Nominatim OpenStreetMap, retorna "Rua X, Bairro Y")

2. src/services/location.service.ts
   - startTracking(userId, mode: 'passenger'|'driver'): void
     * Usa expo-location com accuracy BALANCED
     * Intervalo: 15 segundos quando activo, 60s quando bateria < 20%
     * Publica localização em tabela 'locations' via upsert
     * Guarda subscription ID para poder parar depois
   - stopTracking(userId): void
     * Remove subscription, define is_active = false na tabela
   - publishLocation(userId, coords, mode): Promise<void>
     * Upsert na tabela locations com todos os campos
   - getLastKnownLocation(userId): Promise<Location | null>
   - requestPermissions(): Promise<boolean>
     * Pede permissão foreground e depois background
     * Se negada, guarda estado e mostra mensagem explicativa
   - Listener de bateria: expo-battery para reduzir frequência quando baixa

3. src/services/realtime.service.ts
   - subscribeToContactsLocations(userId, contactIds, callback): RealtimeChannel
     * Subscreve ao canal Supabase Realtime 'locations'
     * Filtra para receber apenas actualizações dos contactIds fornecidos
     * Callback recebe NearbyDriver[] ou NearbyPassenger[] actualizado
   - subscribeToRideUpdates(rideId, callback): RealtimeChannel
     * Subscreve a mudanças de status de uma corrida específica
   - unsubscribe(channel): void
   - unsubscribeAll(): void

4. src/hooks/useLocation.ts
   - Expõe: myLocation, isTracking, permissionStatus, error
   - startPassengerMode(): void → activa tracking em modo passageiro
   - startDriverMode(): void → activa tracking em modo motorista
   - stopTracking(): void
   - Detecta automaticamente a paragem mais próxima via reverseGeocode
   - Lida com erros de GPS: sem sinal, permissão negada, GPS desligado

5. src/hooks/useNearbyContacts.ts
   - Usa useLocation + realtimeService em conjunto
   - Retorna: nearbyDrivers: NearbyDriver[], nearbyPassengers: NearbyPassenger[]
   - Actualiza em tempo real via Supabase Realtime
   - Inclui distância e ETA calculados localmente (mais rápido que servidor)
   - Auto-ordena por ETA crescente
   - Para quando o componente desmonta (cleanup automático)

6. Teste: src/utils/__tests__/geo.test.ts
   - Testa haversineDistance com coordenadas conhecidas de Luanda

1. src/services/notifications.service.ts
   - registerForPushNotifications(): Promise<string | null>
     * Pede permissão ao utilizador
     * Obtém Expo Push Token
     * Guarda token na tabela users via Supabase
   - sendLocalNotification(title, body, data?): void
     * Notificação local imediata (sem servidor)
   - scheduleNotification(title, body, trigger): void
   - handleNotificationReceived(notification): void
     * Dispatcher: redirige para ecrã correcto conforme notification.data.type
   - Tipos de notificação a tratar:
     * 'driver_approaching' → abrir ecrã principal com card do motorista
     * 'ride_request' → abrir bottom sheet de confirmação (modo motorista)
     * 'ride_accepted' → abrir tracking da boleia
     * 'sos_alert' → alerta urgente (toca som mesmo em silêncio)
     * 'contact_waiting' → passageiro da rede está na paragem

2. backend/src/services/push.service.ts (lado do servidor Node.js)
   - sendPushToUser(userId, title, body, data): Promise<void>
     * Busca expo_push_token do utilizador na base de dados
     * Envia via Expo Push API (https://exp.host/--/api/v2/push/send)
   - sendPushToContacts(userId, radius_km, title, body, data): Promise<void>
     * Busca contactos activos do utilizador num raio X km
     * Envia push a todos (batch de max 100 por chamada à Expo API)
   - sendSosAlert(userId, lat, lng): Promise<void>
     * Notifica contacto de emergência com localização
     * Envia SMS via AfricasTalking como backup (para garantia)
